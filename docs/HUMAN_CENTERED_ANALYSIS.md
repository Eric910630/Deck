# 人类中心化分析方案

## 🎯 核心理念

**从"机器友好"转向"人类友好"**

系统应该按照人类理解文档的真实流程进行分析，而不是从技术角度拆解。

---

## 📖 人类理解文档的真实流程

### 1. **通读理解** - 先理解整体思想和含义
- 这个文档在讲什么？
- 核心主题是什么？
- 想要传达什么价值主张？
- 目标受众是谁？

### 2. **板块拆分** - 识别各个板块及其核心思想
- 文档分为哪几个部分？
- 每个部分在讲什么核心观点？
- 板块之间的逻辑关系是什么？

### 3. **论证逻辑** - 识别支撑核心思想的论据
- 每个板块用了什么论证方式？
- 有哪些证据点支撑核心观点？
- 论证的逻辑链条是什么？

### 4. **支撑材料** - 数据、图表等佐证材料
- 有哪些数据支撑？
- 有没有图表、表格？
- 有没有案例、引用？

### 5. **表达风格** - 语言风格、文化特征
- 语言是正式还是非正式？
- 语调是积极还是谨慎？
- 有没有文化特征（如中文表达习惯）？

### 6. **呈现形式** - 格式、布局、视觉呈现
- 布局风格是什么？
- 字体排版如何？
- 视觉层次如何？

---

## 🔄 对比：机器友好 vs 人类友好

### 机器友好的7层分析（旧方案）

```
1. 物理结构层 - 段落、表格、章节
2. 格式特征层 - 字体、字号、加粗
3. 内容语义层 - 标题-内容块
4. 列表结构层 - 编号列表、项目符号
5. 表格数据层 - 表格结构
6. 主题/话题层 - 关键词聚类
7. 逻辑关系层 - 顺序、层级、对比
```

**问题**：
- ❌ 从技术角度拆解，不符合人类思维
- ❌ 缺少整体理解
- ❌ 缺少论证逻辑分析
- ❌ 缺少表达风格分析

### 人类友好的6层分析（新方案）

```
1. 通读理解层 - 整体思想、主题、价值主张
2. 板块结构层 - 各个板块及其核心思想
3. 论证逻辑层 - 论据和论证方式
4. 支撑材料层 - 数据、图表、案例
5. 表达风格层 - 语言风格、文化特征
6. 呈现形式层 - 格式、布局、视觉呈现
```

**优势**：
- ✅ 符合人类理解流程
- ✅ 先整体后局部
- ✅ 关注思想和逻辑
- ✅ 适合生成人类友好的汇报文档

## 📊 新方案详细设计

### 第1层：通读理解层

**目标**：理解文档的整体思想、主题、目的和核心价值主张

**分析内容**：
- 核心主题（文档在讲什么）
- 价值主张（想要传达什么价值）
- 文档目的（汇报/提案/介绍/分析）
- 目标受众（管理层/技术团队/业务团队/投资者）
- 关键短语（强调的内容）

**示例输出**：
```json
{
  "core_theme": "技术产品商业化",
  "value_propositions": [
    "降低运营成本40-60%",
    "提升转化效率20-35%",
    "加速业务智能化转型"
  ],
  "purpose": "汇报",
  "target_audience": "管理层",
  "key_phrases": ["朋友云", "BefriendsAI", "数据中心平台"]
}
```

---

### 第2层：板块结构层

**目标**：识别各个板块及其传递的核心思想

**分析内容**：
- 板块数量
- 每个板块的主题
- 每个板块的核心思想
- 板块包含的幻灯片
- 板块内容摘要

**示例输出**：
```json
{
  "total_sections": 4,
  "sections": [
    {
      "section_index": 0,
      "theme": "技术产品商业化-文档",
      "core_idea": "全链路AI赋能解决方案",
      "slides": [0],
      "content_summary": "核心价值主张：降低运营成本40-60%..."
    },
    {
      "section_index": 1,
      "theme": "25年技术简单回顾",
      "core_idea": "回顾技术发展历程",
      "slides": [1],
      "content_summary": "1.朋友云做了多少需求、工时、系统..."
    }
  ]
}
```

---

### 第3层：论证逻辑层

**目标**：识别每个板块的论据和论证方式

**分析内容**：
- 论证类型（数据论证/案例论证/对比论证/因果论证）
- 证据点（具体的数据、案例、对比点）
- 论证逻辑链条

**示例输出**：
```json
{
  "arguments": [
    {
      "section_index": 0,
      "section_theme": "技术产品商业化-文档",
      "argument_types": ["数据论证", "案例论证"],
      "evidence_points": [
        "数据: 40-60%",
        "数据: 20-35%",
        "要点: 降低运营成本"
      ]
    }
  ]
}
```

---

### 第4层：支撑材料层

**目标**：识别数据、图表、案例等佐证材料

**分析内容**：
- 数据点（百分比、数值等）
- 图表（如果有）
- 表格（如果有）
- 案例（客户案例、项目案例）
- 引用（如果有）

**示例输出**：
```json
{
  "total_data_points": 15,
  "total_cases": 3,
  "materials": {
    "data_points": [
      {"slide_index": 0, "data": "40-60%", "context": "降低运营成本"},
      {"slide_index": 0, "data": "20-35%", "context": "提升转化效率"}
    ],
    "cases": [
      {"slide_index": 2, "content": "客户案例：某直播公司..."}
    ]
  }
}
```

---

### 第5层：表达风格层

**目标**：分析语言风格、表达方式、文化特征

**分析内容**：
- 正式程度（正式/非正式/中性）
- 语调（积极/谨慎/中性）
- 文化特征（强调团队协作/价值导向/数据驱动等）
- 数字使用频率
- 表情符号使用

**示例输出**：
```json
{
  "formality_level": "中性",
  "tone": "积极",
  "cultural_features": [
    "强调团队协作",
    "强调价值导向",
    "数据驱动表达"
  ],
  "use_of_numbers": 25,
  "use_of_emojis": 2
}
```

---

### 第6层：呈现形式层

**目标**：分析格式、布局、视觉呈现方式

**分析内容**：
- 布局风格（16:9/4:3等）
- 字体排版（字体、字号、加粗使用）
- 视觉层次（标题层级、正文层级、强调数量）
- 颜色使用（颜色种类、颜色值）

**示例输出**：
```json
{
  "layout_style": {
    "aspect_ratio": "16:9",
    "width_cm": 33.867,
    "height_cm": 19.05
  },
  "typography": {
    "font_sizes": [26.0, 15.0, 14.0],
    "font_names": ["Arial"],
    "bold_usage_count": 10
  },
  "visual_hierarchy": {
    "title_levels": 5,
    "body_levels": 8,
    "emphasis_count": 10
  }
}
```

## 💡 关键改进点

### 1. 从"技术拆解"到"思想理解"
